# Ревизия 2D / A3

Изменения сделаны в отдельной копии проекта. Прежний архив, исходный репозиторий и опубликованный сайт не изменены. Публикация этой ревизии не выполнялась.

## Что реализовано

- Один замкнутый контур Leaflet, который не пересоздаётся при каждом движении вершины. Перетаскивание, клавиатура, вставка вершины на ребре, отмена последней точки и сохранение границ.
- Проверка самопересечений, касаний и вырожденных рёбер. Неверно нарисованный контур можно исправить; ошибочное перемещение корректной границы откатывается.
- Площадь полигона и размер окна загрузки показаны до расчёта. Минимальная площадь 0,01 км²; максимальное прямоугольное окно данных 100 км². Узкий или вогнутый контур также проверяется по своему окну загрузки.
- География, существующие ЭЗС, ячейки спроса и кандидаты обрезаются по реальному контуру. Здания, вода и внутренние кольца мультиполигонов учитываются при отборе площадок.
- Локальная карта и данные большей части Москвы из одной выгрузки OpenStreetMap / BBBike от 10.10.2026. Подложки не накладываются друг на друга. География помещена в отдельный нижний слой, который не закрывает выделение.
- Загрузка данных с отменой, сменой публичного источника, ограничением ответа и сохранением успешно загруженного контура в IndexedDB. При ошибке не подставляется другой район.
- Поставляемый тестовый район ЗИЛ с явно синтетическим спросом и экономикой, реальными объектами карты и топ-1/5/10 из исходной модели района.
- Сцена бобра с подключением кабеля во время загрузки/расчёта. Числа прогресса приходят из расчётного worker; искусственной задержки нет. Отмена сохраняет границы и параметры.
- Обзор 3D: подпись и кнопки в общем адаптивном контейнере. Продолжение по кнопке; автопоказ по желанию. После выхода восстанавливаются исходные год, сценарий и решения.
- Выбранный A3 на главной: закреплённая инвестиционная история 2026 → 2027 → 2030 → 2035, последовательное раскрытие этапов, движение карты и линии развития. Отдельная карточка 2D ведёт к рабочему расчёту. Схема не выдаётся за результат модели.
- D1 / B4 / C1: реальная вечерняя фотография Москвы-Сити, движущееся сечение Tesla и спокойные сферы вокруг 2D.
- Общая последовательность Tesla: подъезд → подключение → ток. Убраны лишние кабели исходного фото ЭЗС, добавлен концептуальный шильдик «Росатом». Внедрены D1 (вечерний фотографический фон) и B4 (сечение по курсору).

## Выбор оформления

Выбраны и внедрены A3, B4, C1 и D1. В `design-options/index.html` сохранена галерея исходных вариантов. B4 показывает иллюстративный движущийся срез по переданному техническому изображению; это композиция разных ракурсов, не проверенная заводская CAD-модель. При уходе курсора с автомобиля кузов восстанавливается. Клавиатура: стрелки двигают срез, Escape закрывает. На сенсорном экране срез переключается касанием. C1 — спокойные сферы вокруг карты и формы, с ограниченным откликом на курсор.

## Запуск

Node.js 20+; установка зависимостей и сборка не требуются:

```sh
npm start
```

Открыть http://localhost:5173. Проверки: `npm test`. Другой порт: `node server.mjs 5196`.

Для сжатых файлов карты нужен правильный `Content-Encoding: gzip`: встроенный Node-сервер и конфигурация Vercel это задают. Простой Python static server для этой ревизии не подходит. Развёртывание Vercel этой ревизии не проверялось.

## Как показать 2D

1. Открыть `district.html` и нажать «Открыть тестовый район».
2. Переместить вершину, увидеть новую площадь, сохранить контур.
3. Дождаться загрузки географии, нажать «Найти лучшие места».
4. Сравнить кандидатов и существующие ЭЗС на карте. Топ — альтернативы для **одной** новой станции, не совместный план строительства всех точек.
5. Открыть экономику кандидата и серверную сверку. Затем перейти в иной московский район и задать обоснованные параметры спроса.

## Границы данных

Локальный набор: 55.571–55.915 N, 37.323–37.879 E. Это покрытие выгрузки, не административная граница всей Москвы. За его пределами используются онлайн-источники, сохранённая география того же контура или импорт полного OSM JSON. В проверке публичные Overpass-источники для Казани/Санкт-Петербурга отвечали ошибками; бесперебойный онлайн-доступ не подтверждён. Реальная выгрузка центра Казани включена как пример импорта в `data/examples/kazan-center-osm.json` и прошла расчётный тест.

Спрос, доступная мощность, стоимость подключения и экономика остаются пользовательскими допущениями до получения подтверждённых данных. Отсутствие объектов в OSM не означает отсутствие станций в реальности. Прединвестиционный результат требует проверки участка, подъездов, подключения и данных оператора.

Новые внешние библиотеки не добавлены. Шесть основных модулей 3D-модели совпадают с исходной main; сравнение записано в `core-preservation.json`. Расчётное ядро 2D сохранено, изменена обработка геометрии с внутренними кольцами.
