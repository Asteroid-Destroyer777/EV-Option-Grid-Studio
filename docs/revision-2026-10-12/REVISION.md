# EV-Option Grid — изменения 12 октября 2026

Рабочая ревизия существующего проекта. Исходная версия Git `becc27b` сохранена. Публикация в GitHub и изменение действующего хостинга не выполнялись.

## Запуск

Нужен Node.js 22 или новее. Дополнительные пакеты и сборка не требуются.

```sh
npm start
```

Открыть http://localhost:5173. Для другого порта: `node server.mjs 5196`.

Страницы: `/index.html` — презентация, `/district.html` — произвольный район, `/polygon3d.html` — существующий полигон ЗИЛ. Локальная карта ЗИЛ, шрифты, Leaflet, Three.js и графические файлы включены в проект. Вне покрытия ЗИЛ нужна собственная география или доступный онлайн-источник.

## Что изменено

- Первый экран: настоящая фотография Москва-Сити, изображение Tesla Model X и каталожное изображение реальной промышленной ЭЗС. Прокрутка синхронизирует подключение кабеля, индикатор и ток по условной подземной схеме. На главной нет WebGL-сцены. Режим уменьшения движения определяется системной настройкой; отдельная кнопка анимаций убрана.
- Оранжевый блок заменён фрагментом исходной карты и контуром территории. Исправлены регистр подписей, положение маркеров решений и оформление финансовых формул.
- 2D: рисование и редактирование контура, отсечение объектов по полигону, автоматическая загрузка локальной географии при расчёте, поиск 1/5/10 альтернативных площадок в отдельном worker. Вода, здания и непосредственное совпадение с существующей ЭЗС исключаются. Неизвестные подъезд, право на участок и доступная мощность требуют подтверждения.
- Каждый кандидат проходит существующий `calculateDistrict`: модель Хаффа, почасовое обслуживание, конкуренция, энергетическая ёмкость, ввод, денежные потоки, дисконтирование и чувствительность. Сравнение по спросу 50/100/150% минимизирует максимальное сожаление; вариант без строительства учитывается. Топ — разные места для одной ЭЗС, а не оптимизированный план одновременного строительства десяти станций.
- Пассажиропотоки меняют относительное распределение заданного спроса; суммарные сессии сохраняются. Без численных наблюдений используется транспортная доступность с явной пометкой «прокси». Доступны импорт и неполный архив Технопарка за I квартал 2021. Привлекательность учитывает торговлю, питание и парковки; влияние задаётся пользователем.
- Паспорта площадок позволяют сравнить индивидуальные `gridKW`, `capex`, `opex`, `posts`, `postKW`. Источник численных параметров обязателен. После импорта поиск ограничен этими площадками.
- В 3D: станция из пользовательского Blender-файла без большого солнечного навеса, экземпляры оборудования объединены по материалам. Добавлены 15 реальных архивных координат входов метро/МЦК, стилизованные павильоны и навигация к ним. При выборе входа открывается разрез старой геометрии зданий, чтобы вход не скрывался в укрупнённом здании исходного набора.
- Обзор территории останавливается на каждом кадре до нажатия «Следующий кадр». Автопоказ включается отдельно и оставляет 9 секунд на чтение после полёта. Подпись станции показывает фактическую загрузку текущего сценария.
- Бобр использует серверный Responses API OpenAI; ключ не находится в браузере. Нет инструментов исполнения команд, записи файлов или изменения проекта. Сообщения выводятся как обычный текст. Расчётный контекст валидируется и пересчитывается сервером. Ограничены размер вопроса, история, время и частота обращений.

Новые внешние JS-библиотеки не добавлены. Анимации используют CSS/SVG, Web Animations и существующее расчётное/графическое ядро.

## Помощник

Создать `.env.local` по `.env.example`, задать `OPENAI_API_KEY` и при необходимости `OPENAI_MODEL`. Перезапустить сервер. Ключ хранится только на сервере. В ZIP нет ключа и рабочего `.env.local`.

Реальный вызов предоставленного ключа вернул `credit_balance_exhausted` (HTTP 429). Поэтому свободный GPT-диалог пока недоступен. Локальные объяснения модели и показателей выбранной станции работают; после пополнения API-баланса интеграция сможет обращаться к сервису. Проверка API-параметров выполнена также изолированным тестом с подменённым транспортом.

Лимиты текущего сервера: 5 вопросов в минуту на IP и 200 в сутки на процесс. Для публичной установки с несколькими экземплярами нужен общий лимитер и политика доступа/бюджета. Этот прототип не выдаёт инженерных разрешений и не обещает инвестиционный результат.

## Форматы импорта

Пассажиропоток — массив:

```json
[{"lat":55.694,"lon":37.665,"passengersPerDay":25000,"source":"Ссылка на измерения или открытый набор","period":"Год/квартал/период"}]
```

Пример выше показывает схему, а не фактический пассажиропоток. Проверенная архивная запись включена в `data/passenger-observations.json`.

Площадки — массив:

```json
[{"name":"Площадка A","lat":55.71435,"lon":37.6574,"gridKW":300,"capex":9000000,"opex":500000,"posts":4,"postKW":150,"parameterSource":"Ссылка на технические условия и смету"}]
```

Координаты должны лежать в выбранном контуре. `example-sites.json` — только проверочные сценарные значения. `example-district.json` — полный воспроизводимый пример исходной модели и географии.

## Проверка для пилота

Сохранены все прежние расчётные тесты. Дополнительно проверяются сохранение спроса при новых критериях, границы полигона, отсутствие фиктивного эффекта при нулевой мощности, индивидуальные сметы, изоляция помощника. Результаты серверной сверки и расчётного времени на этой машине сохранены в `verification-model.json`.

Для проверки эффективности, описанной в исходном задании, нужны актуальные фактические сессии и нагрузки оператора, реальные условия подключения, доступные участки и сметы. На этих входах следует сравнить модельное размещение с геометрическим центром/обычным выбором привлекательного места, отложить часть наблюдений для проверки прогноза и провести пилот одной станции. Интерфейс уже показывает сравнение, обслуживание, перераспределение, ограничения и экономику; отсутствие подтверждённых данных не заменено выдуманными фактами.

## Работа без VPN и размещение

Удалены зависимости первого экрана от внешних картинок/шрифтов и WebGL; необходимые файлы размещены локально. ЗИЛ имеет встроенную векторную подложку, поэтому при отказе тайлов расчёт и выбор территории доступны. Онлайн-OSM и GPT требуют доступа к соответствующим сервисам.

Доступность прежнего домена Vercel у конкретного провайдера нельзя исправить одним изменением ZIP. По просьбе пользователя действующий сайт не перепубликовывался. Включён Dockerfile для размещения на доступном сервере:

```sh
docker build -t ev-option-grid .
docker run --rm -p 5173:5173 --env-file .env.local -e HOST=0.0.0.0 ev-option-grid
```

Для внешнего доступа нужны домен и HTTPS на выбранном хостинге. Размещение следует делать после пользовательской проверки этой версии.

Исходник станции включён как `assets/station-source.blend`. Повторный экспорт без навеса: `blender -b assets/station-source.blend -P tools/export_charger.py -- assets/charger-model.json`.
