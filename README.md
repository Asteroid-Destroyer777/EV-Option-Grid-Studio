# EV-Option Grid · N2 / карта с подписями / Крутя

Ревизия с исправленным 2D-полигоном, локальной географией Москвы, выбранной инвестиционной историей и вечерней сценой Tesla. Предыдущая версия и опубликованный сайт сохранены. GitHub и сайт этой ревизией не обновлялись.

Запуск: `npm start` → http://localhost:5173. Node.js 20+, без установки пакетов и без сборки. Проверки: `npm test`.

[Изменения и сценарий презентации](docs/revision-2d-v2/REVISION.md) · [Фактические проверки](docs/revision-2d-v2/QA.md) · [Источники](docs/revision-2d-v2/SOURCES.md).

Выбраны A3 — инвестиционная история, N2 — мягкий круговой рентген Tesla, C1 — спокойные сферы, D1 — кинематографичный вечер. Галерея макетов: `design-options/index.html`. Сечение иллюстративное, по пользовательскому референсу; точная инженерная компоновка не подтверждена.

Локальный московский набор имеет ограниченное географическое покрытие. В других местах нужны доступный онлайн-источник или импорт полной географии. Встроенный тест использует синтетические спрос и экономику. Подробности и границы данных указаны в документации ревизии.

Python static server не задаёт необходимые заголовки сжатых тайлов; используйте входящий в проект Node-сервер.

# План зарядной сети — прототип 0.4
Проект команды subatomic для проблемы № 03 «Зарядка электромобилей в мегаполисах».
Заказчик: ООО «Росатом Сеть зарядных станций».

## Новое: отдельный расчёт любого района
В меню 3D-полигона нажмите «2D · Выбрать другой район»: откроется отдельная вкладка `district.html`. Геометрия и расчётное ядро 3D-полигона не заменяются.

1. Переместите 2D-карту в нужный город или введите координаты. Нарисуйте контур или нажмите «Выбрать видимую область». Вершины можно перемещать; площадь и лимит загрузки отображаются заранее. Поддерживается замкнутый полигон от 0,01 км², окно загрузки до 100 км², не более 200 зарядных объектов; административные границы автоматически не распознаются.
2. Загрузите объекты открытой карты. Если источник недоступен, импортируйте JSON Overpass или начните ручной набор и расставьте зарядки на карте. Наличие публичного источника не гарантирует доступность и полноту реестра.
3. Щелчком по карте задайте новую площадку. В реестре можно уточнить посты, мощность и исключить дубль из сценария — сама OpenStreetMap не изменяется.
4. Введите общий зарядный спрос, его источник, лимит подключения и экономику. «Учебные допущения» нужны только для демонстрации; они не являются измерениями района.
5. Рассчитайте площадку. Результат включает сравнение «до / после», долю перетока от конкурентов, почасовое обслуживание, финансовые потоки и чувствительность 50/100/150%.
6. Сохраните JSON или проверьте результат на сервере. Импорт пересчитывает итог из входов, а не доверяет сохранённым цифрам.

В 2D применяется независимая упрощённая модель предварительного отбора площадки: сетка 20×20, вес «1 + число зданий», Хафф, прямые расстояния, один пользовательский профиль, лимит мощности площадки. Существующие объекты считаются конкурентами. Совместная сеть, накопитель и электробусы в этот режим не перенесены; они не подменяются вымышленными данными. Расширенная почасовая энергомодель 3D-полигона сохранена отдельно.

При проверке 1 октября публичный Overpass отвечал ошибками 406/504; резервный экземпляр не ответил вовремя. Импорт и ручной режим работают независимо. Для регулярного использования заказчиком нужен согласованный геосервис или своя выгрузка оператора, а не обещание бесперебойной работы бесплатного источника.

Исправления интерфейса: обзор района закрывается крестиком или Escape и возвращается отдельной кнопкой; подбор траектории работает в фоновом потоке с постоянным сообщением о результате, включая рекомендацию не строить.

## Важное ограничение
Это прединвестиционный сценарный прототип на реальной географии, а не подтверждённый прогноз и не инженерный цифровой двойник. В версии 0.3 подключено переданное пользователем исследование: география открытой карты, 512 районных ячеек спроса, 17 конкурентов, распределение Хаффа и реестр 268 групп зарядных объектов Москвы. Средняя энергия ≈25,2 кВт·ч выведена из опубликованных округлённых агрегатов Росатома. Спрос — оценка модели, не журнал сессий; загрузка 10% взята из неподтверждённого пересказа ответов заказчика. Сетевые мощности, тарифы, сметы, часовые профили и сроки остаются допущениями. Их нельзя выдавать за сведения оператора.

## Что перенесено из исследования
Раздел «Данные исследования» содержит происхождение чисел, сверку исходного и пересчитанного спроса, распределение между своей сетью и конкурентами, переключение спроса 50/100/150%, исходные ссылки и зоны поиска новых площадок. Увеличение постов перераспределяет рынок, а не создаёт клиентов из ничего. Далее спрос проходит через почасовую пропускную способность, сетевой лимит, накопитель и денежные потоки.

Исходные файлы сохранены в `research/`. Модуль данных воспроизводится командой `npm run research:build` (Python 3, только стандартная библиотека). Для обычного запуска Python не нужен. Подробности исправлений и границы переноса — `INTEGRATION.md`. Проверка прогноза в исходном исследовании не пройдена; это явно показано в интерфейсе.

## Запуск
Нужен Node.js версии 20 или новее. Установка пакетов и сборка не требуются.

```sh
npm start
```

Откройте http://localhost:5173. Команда `node server.mjs 5180` запускает на другом порту.
Трёхмерной карте нужен браузер с WebGL2. Демонстрационный пролёт включается кнопкой «Обзор территории», автоматического пролёта нет.
Для статического интерфейса со сжатыми тайлами и серверной сверки используйте Node.js.

## Проверка
```sh
npm test
```
Тесты проверяют сохранение спроса и энергии, часовые ограничения сети, запас накопителя, солнечную выработку ночью, сроки ввода, однократную подготовку площадки, денежные потоки, кэш и валидацию запросов. В интерфейсе: «Паспорт расчёта» → «Проверить расчёт на сервере».

## Как показать заказчику
1. Откройте станцию и сравните 2026, 2030, 2035 годы в трёх сценариях.
2. Выберите действие в разделе станции и посмотрите изменение соседних станций.
3. В «Плане инвестиций» проверьте год принятия и срок ввода.
4. В «Паспорте расчёта» покажите спрос по часам, энергию узла, формулы, окупаемость и денежные потоки.
5. Откройте «Данные исследования», сравните спрос 50/100/150%, вернитесь к результатам и покажите изменение расчёта. Затем скачайте паспорт: он включает исследовательские входы, контрольные суммы исходников, предпосылки и результаты.
6. Отдельно назовите незакрытые требования из REQUIREMENTS.md.

ЧПС — чистая приведённая стоимость; ВД — внутренняя доходность. Отрицательная стоимость и отсутствие окупаемости — допустимые результаты, а не ошибки, которые нужно скрыть.
«Перегрузка» означает отсутствие устойчивой стационарной очереди в приближении модели. Это не обещание конкретного времени ожидания.

## Серверная часть
`POST /api/calculate` принимает объект с полями `dataset`, `year`, `scenario`, `decisions`.
Формат входных станций и узлов показан в выгрузке из паспорта. Ответ содержит версию модели, параметры, почасовые результаты и экономику. Действуют ограничения размера тела, числа узлов, станций и решений; проверяются диапазоны параметров и ссылки.

Локальный Node.js-сервер и функция Vercel используют одно расчётное ядро. Браузер работает автономно, сервер используется для воспроизводимой проверки. Совпадение двух запусков одного ядра не является независимой научной валидацией.
Сервер не сохраняет пользовательские планы. Авторизация, многопользовательская база, тарифный биллинг и интеграции с оператором в прототип не входят. Для промышленного размещения нужны ограничение частоты запросов, мониторинг и нагрузочное тестирование.

## Публикация
В проекте есть функция Vercel `api/calculate.js`. Загрузите содержимое этой папки в связанный репозиторий или используйте обычный процесс публикации Vercel: без фреймворка, без команды сборки, корень проекта — эта папка.
Действующий сайт пользователя автоматически не изменён; публикация данной версии отдельно не выполнялась.

## Устройство
- `src/simulation/engine.js` — почасовой спрос, обслуживание, переток и энергия.

- `tools/integrate_research.py` — воспроизводимый перенос исследовательского архива.
- `src/simulation/economics.js` — прирост денежных потоков относительно базового плана.
- `src/simulation/recommend.js` — робастное сравнение рассмотренных пакетов без знания будущего.
- `src/simulation/service.js` — валидация и серверный расчёт.
- `src/simulation/params.js`, `src/data/dataset.js` — открыто заданные допущения.
- `src/ui/audit.js` — паспорт и выгрузка.
- `tests/model.test.mjs`, `tests/research.test.mjs`, `tests/district.test.mjs` — исходные проверки; всего в этой ревизии 39 автоматических тестов.
- `src/district/` — независимые карта, модель, источник и интерфейс произвольного района.
- `api/district.js` — загрузка публичной географии и серверная сверка районного расчёта.
- `REQUIREMENTS.md` — честный статус требований и необходимые данные.

## Правки 13 октября 2026

2D: подписи OSM (метро, железнодорожные станции, районы, улицы), инструменты вынесены из карты, дополнительные критерии в раскрываемой секции. Все поля/импорты/отчёты сохранены. Колесо над картой меняет масштаб; в конце прокрутки панели параметров колесо продолжает листать страницу. Бобр остаётся минимум 5 секунд, готовность расчёта обозначается отдельно.

N2: круговое раскрытие Tesla по двум осям и двойная неоновая подземная трасса. Клавиатура: четыре стрелки, Enter, Escape; сенсорный экран: касание. Это иллюстрация устройства, не инженерная CAD-модель.

3D: собственная геометрическая модель фасада «Острова мечты» на контуре исходного OSM, обновлённые павильоны метро на сохранённых архивных координатах и более заметный трафик по исходному дорожному графу. Архитектура иллюстративная, не геодезическая реконструкция. Фоновое движение не считается наблюдаемым транспортным потоком.

### Крутя

Серверный помощник поддерживает Ollama, xKiro, SEA-LION, OpenRouter, Gemini и прежний OpenAI. Подтверждён живой диалог через Ollama `gemma4:31b`; остальные проверенные сервисы не вернули генерацию (см. QA). Для подключения из архива скопируйте `.env.example` в `.env.local`, заполните `OLLAMA_API_KEY`, установите `ASSISTANT_PROVIDER=Ollama` и запустите/перезапустите сервер. Ключи в архив не входят. На Vercel задаются серверные переменные окружения.

Помощник получает серверный расчёт и последние реплики, объясняет проект, не имеет инструментов изменения файлов или модели. Имя, время Москвы и погода обслуживаются отдельно; данные погоды — модельная оценка Open-Meteo. Чужая тематика отклоняется. Без LLM доступна локальная справка.

Подробности проверки: `docs/revision-2026-10-13/QA.md`. Четыре первоначальных варианта: `design-options-v3/index.html`.
